# Voice Lab Director — presenter-onboarding

Goal: ~8 candidate voices the owner can compare fairly. Tool: `voice_lab` (`build_candidates`).

- **Kokoro blends:** weighted averages of 2–3 preset style vectors + speed (4 candidates, built locally).
- **Chatterbox (MIT, MLX):** clone the owner from `raw/voice_read.*` and blend with 2–3 donor voices (Kokoro presets) at ~70/30, 50/50, 30/70, varying exaggeration/cfg/pitch slightly (4 candidates). Chatterbox runs from its own venv (`lib/chatterbox_runner.py`; chatterbox-mlx pins torch 2.8). Verified API (fix round 1): `conds.t3.speaker_emb` (1×256) and `conds.gen['embedding']` (1×192) are interpolated between the owner's reference clip and Kokoro donor voices; the acoustic prompt tokens/features stay the owner's (so a blend is *owner prompt + blended speaker embeddings*, not a full latent mix). Chatterbox sometimes stops early (EOS) and drops the end of what it was asked to say. **Fix (real-profile round):** the owner reference is the cleanest 10 s of `raw/voice_read.*` (`lib/voice_lab.make_voice_reference` → `raw/working/voice_ref.wav`; Chatterbox only hears ~10 s, so the whole 3-minute file gave it whatever the recording started with), synthesis is done **per sentence**, each sentence is ASR-checked (coverage ≥ 0.85 **and** the last words were actually heard, `chunk_ok`), and only a failing sentence is re-rolled with a new seed (up to 4 takes). The assembled paragraph is then checked as a whole (≥ 0.92); a candidate that is still incomplete is labelled with a truncation warning on the page — tell the owner. A Chatterbox candidate **can be locked** (`lock_voice` with `speed`, e.g. 0.95 for 5% slower): the profile stores the blend recipe, `raw/working/voice_ref.wav`, the donor reference clips (`voice/donors/`) and the speed; `mlx_tts` then narrates with it through the same per-sentence ASR-checked path. Chatterbox has no native speed control, so speed is a pitch-preserving time-stretch (rubberband, else atempo) applied before the polish chain; captions and scene timing measure the slowed file. If the backend is missing or doesn't expose it, report exactly that and **ask the owner before switching engines** (e.g. Qwen3-TTS base cloning in `mlx-audio`) — never substitute silently. Weights ≥ 500 MB need disk check + owner OK.
- Every candidate reads the **same ~20 s tutorial-style paragraph** through the **same polish chain** (high-pass 80 Hz, presence EQ, de-ess, light compression, loudness normalize) — fair comparison.
- Output `voice/candidates/index.html` (local page: player + recipe per candidate; unavailable candidates are labeled with the reason). Tell the owner to open it and name a candidate id.
- The voice need not match the owner's real voice; it must be consistent, attractive, distinctive. Chatterbox output carries an inaudible Perth watermark (accepted).

## Failure handling
- **Candidates unavailable** (e.g. Chatterbox not installed or no speaker-embedding access): label them unavailable with the exact reason on the page, deliver the rest, and 🛑 ask before any engine substitution.
- **All candidates rejected →** second round: ask what was off (too deep/bright/slow/robotic/too unlike you), choose **new blend ratios** (e.g. shift Kokoro weights ±20 %, change donor voices, change speed/exaggeration), rebuild into `voice/candidates/round2/` with the same ~20 s paragraph and polish chain, and regenerate the page with both rounds. Keep earlier rounds so the owner can go back.
- **Synthesis error on one candidate:** record the error in its recipe entry, continue with the rest.
